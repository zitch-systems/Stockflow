# StockFlow — Platform Audit (June 2026)

End-to-end audit across functionality, security, performance, SEO, accessibility,
code quality, architecture and DevOps. Scope: this repo is a **static, build-less
HTML/JS PWA** served by Netlify / Cloudflare Pages, with **Supabase** (Postgres +
Auth + Storage + Realtime) as the only backend, talked to directly from the
browser with the public anon key.

This document records findings and prioritisation. The SEO / security-header /
cache fixes in the same change are **already applied** (see "Fixes shipped");
everything else is recommendation-only because it needs the live DB (not in this
repo) or larger refactors.

## 2. Fixes shipped in this change

All verified against `npm test` (auditor green) and JSON-LD validated as parseable.

### SEO (was the biggest concrete gap)
1. **Added `robots.txt`** — none existed. Allows public pages, disallows the
   authenticated dashboard shells + password-reset flows, points to the sitemap.
2. **`landing.html`** — added `canonical`, full **Open Graph** + **Twitter Card**
   tags, and **JSON-LD** (`Organization`, `WebSite`, `SoftwareApplication`,
   `FAQPage`). FAQ schema text mirrors the visible on-page FAQ (rich-result safe).
3. **`login.html` / `signup.html`** — added `meta description`, `canonical`,
   `robots: index,follow`.
4. **`forgot-password` / `reset-password` / `404` / `index`** — `robots: noindex`
   (utility/redirect pages that should not be indexed).
5. **All four dashboards** (`rep`/`manager`/`owner`/`admin`) — `robots:
   noindex, nofollow`. Their HTML shells are publicly fetchable even though the
   data is auth-gated; they should never appear in search.
6. **`sitemap.xml`** — added `lastmod`, dropped the bare `/` entry (it is an
   noindex JS redirector; `landing.html` is the canonical home) and re-prioritised.

### Security / Infra
7. **`_headers` (Cloudflare Pages) was missing `Content-Security-Policy`** even
   though `netlify.toml` defines one and the file comment claims they are kept
   "identical regardless of host." A Cloudflare deploy therefore shipped with **no
   CSP**. Added the matching policy. *(Severity: Medium — defence-in-depth gap.)*

### Bug / DevOps
8. **`_headers` immutable-cache rules never matched** — they referenced
   `/supabase_min.js` and `/html2canvas_min.js` (underscores) but the real files
   are `supabase.min.js` / `html2canvas.min.js` (dots). The 1-year immutable
   caching silently fell back to defaults on Cloudflare. Fixed the filenames.
   *(Severity: Low — perf/caching only.)*

## 3. Security Report (OWASP-oriented)

**Trust model:** the DB (RLS + `SECURITY DEFINER` functions) is the *only* real
boundary. `window.sb` and every client value are attacker-controllable. Findings
are therefore judged on "what does the DB enforce", which cannot be inspected
from this repo — so several are **conditional-critical**.

| ID | Severity | Finding | Status |
|----|----------|---------|--------|
| C1 | 🔴 Critical (conditional) | Clients compute & write `total_value`, `rep_holdings.quantity`, prices, payment `status` directly. RLS gates rows, not values → a merely-authenticated user can fabricate stock/debt/sales from the console. | RPCs authored (`02–04`) + frontend wired with fallback. **Verify deployed on live DB.** |
| C2 | 🔴 Critical (conditional) | Privilege escalation: `requireAuth()` recovery trusts user-writable `user_metadata.role`/`tenant_id`; reps update their own `profiles`. If the profiles write policy only checks `auth.uid()=id`, a user can self-assign `role='owner'`. | `01-profiles-rls-hardening.sql` authored. **Verify deployed.** |
| S1 | 🟠 Medium | CSP allows `script-src 'unsafe-inline'`. Required today because every page uses inline scripts + `on*` handlers; weakens XSS mitigation. | Recommend nonce/hash migration (large; see §8). |
| S2 | 🟠 Medium | CSP missing on Cloudflare path. | **Fixed.** |
| S3 | 🟡 Low | No `Strict-Transport-Security` header. | Recommend adding `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload` to `_headers` + `netlify.toml`. |
| S4 | 🟡 Low | Stored-XSS class (tenant data rendered in a higher-priv session). | Mitigated in-repo: `escapeHtml` + the auditor's `checkInlineHandlerXss` gate. Keep enforcing. |
| S5 | ℹ Info | Anon key in client. | **By design** for Supabase; not a finding. Ensure it is the anon (not service-role) key — confirmed pattern in `supabase-client.js`. |

**Recommended next steps:** run the two console probes in
`security-remediation/README.md` against production as a logged-in rep. If either
write succeeds, C1/C2 are confirmed-live-critical and the SQL must be deployed
immediately.

## 4. Functional & Data-Integrity Report

Multi-step financial writes are **not transactional** (the client does sequential
writes). These are real corruption paths on ordinary network blips, not just
attacks:

| Severity | Bug | Evidence | Fix |
|----------|-----|----------|-----|
| 🟠 High | Edit-sale can leave a sale with stale totals and **zero line items** (`delete` then `insert`, no txn; preceding holdings updates unchecked). | `rep-dashboard.html` (edit path) | `edit_sale` RPC (atomic) |
| 🟠 High | Cancel-sale **double-restores stock** (holdings restored before status flip, no idempotency guard) → double-click inflates `rep_holdings`. | `rep-dashboard.html` (cancel path) | `cancel_sale` RPC; flip status first |
| 🟡 Med | Record-sale stock drift — holdings decrement after commit, failure only `console.warn`-ed. | `rep-dashboard.html` (doSell) | `record_sale` RPC |

All three collapse into single server-side transactions once the RPCs in
`security-remediation/` are live. **Until then**, the in-code guards (flip
authoritative status before adjusting stock; double-submit guards) are the only
protection — keep them.

## 8. Code Quality & Architecture

**Strengths**
- A genuinely good **custom static auditor** (`tests/audit.mjs`) that catches dead
  handlers, dead `window.fn()` calls, duplicate IDs, syntax errors and an
  inline-handler stored-XSS class — runs in CI and as a SessionStart hook.
- Strong `CLAUDE.md` documenting the exact footguns (IIFE scoping, escapeHtml).
- Deliberate, defensible "no build step" choice for the stage and team size.

**Technical debt / risks**
- **7k-line single-file dashboards** with multiple top-level script scopes are the
  main maintainability tax. Each `<script>` is its own scope; globals are wired via
  `window.fn = fn` by hand (a documented source of dead-nav bugs).
- **Duplicated head boilerplate** across 11 HTML files (fonts, icons, PWA meta).
  Drift already happened (the `_headers` filename + CSP gaps). A tiny build step or
  server-side include would remove a whole class of "I changed it in one file" bugs
   — but that trades away the zero-build simplicity. Recommend only if the team grows.
- **No automated DOM/E2E tests** — the auditor is static-only. The repo references
  `stockflow-test-v3.html` (RLS tests) but it's `.netlifyignore`d and not in CI.

**Roadmap**
- *Short term:* confirm + deploy the C1/C2 SQL; add HSTS; add the missing a11y
  labels; lazy-load html2canvas.
- *Medium term:* finish moving every financial write to atomic RPCs (table in
  `security-remediation/README.md` §"Full scope"); add Playwright smoke tests for
  the auth + sell happy paths against a Supabase staging branch.
- *Long term:* evaluate a minimal build/include layer to de-duplicate `<head>` and
  enable CSP nonces (removing `script-src 'unsafe-inline'`); consider splitting the
  owner dashboard by tab to cut first-load JS.
